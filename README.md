# UAR (User Access Review)

Oracle APEX application (id **530**, workspace `ct_bsg_apex`, schema `XXUAR`) in which managers periodically review,
approve or deny the Oracle EBS access held by their direct reports, with a permanent audit record. It replaces the
original MVP (app 104), which had no concept of a review period and no real authorization.

Current application version label: `Release 2.0`. APEX 24.2 export.

## What it does
1. An **admin opens a review cycle** (name, period, due date). The app snapshots every responsibility in the feed.
2. Each **manager** sees their direct reports, approves or denies every access item (a denial needs a reason),
   and **submits** their review when every item is decided. Submitting locks their items.
3. Admins watch **per-manager progress**, may reopen a submission, and **close** the cycle at the due date. A closed
   cycle is the permanent audit record.
4. **Audit History** shows every item with who decided what and when, any decision that was later changed, and an
   **Admin Activity** log of what admins did.
5. Employees nobody can review (top of the hierarchy, manager missing from Workday, or not in Workday at all) get an
   admin-assigned reviewer on **Reviewer Assignments**.

## What the system enforces
- Real authorization (`xxcti_uar_security_pkg`): a manager can only review their own reports; **nobody can approve
  their own access, admins included**; the checks live in the database (a trigger on the review items), not just in the
  pages.
- Sign-off is validated on the server (open cycle, real manager, your own review or an admin's, nothing pending);
  admin submit-on-behalf is allowed and logged.
- One open cycle at a time, unique cycle names, period end not before start (database constraints).
- **Closed cycles cannot be deleted**; an open cycle can (opened by mistake).
- Approver and approval date are stamped by a trigger; every change of decision or reason is kept in
  `xxcti_uar_review_items_history`.
- Admin actions (open/close/delete cycle, reopen, submit on behalf, add/remove admin, assign/remove reviewer) are logged
  in `xxcti_uar_admin_log`.
- A reviewer assignment is only accepted when Workday gives no usable manager, the reviewer does not report to the
  employee, and it stops being used as soon as Workday supplies a manager.
- 30-minute idle session timeout; SSO sign-in (Azure AD / OpenID Connect).

## Install and deploy
Do not run files by hand from this repo into DEV/TEST/PROD: use a deployment pack.
- `deploy/<env>-<date>/README_DEPLOY.md` is the step-by-step (pre-flight checks, schema, first admin, app import,
  verification, test checklist, rollback, manifest).
- Build one with `python deploy/make_pack.py deploy/<env>-<date> FRESH` (target has no UAR objects), or
  `... <from-ref>` for an upgrade (`from-ref` = the git ref live in the target). Add `--prod` for the production
  application variant. Hand-write that folder's pre-flight, verify, checklist and README by copying the previous
  pack of the same kind.
- After a pack is deployed and tested, tag the source commit named in its `MANIFEST.txt` (`dev-`, `test-`, `prod-`
  plus the date) and push the tag.
- **SSO credential:** the import creates the web credential `Creation APEX - DEV - PMO` **empty**; enter the Azure
  registration's Client ID *and* secret value, or sign-in fails with `AADSTS900144`.

## Source feeds (must exist before install; the install does not create them)
Fed by an external EBS/Workday process, in schema `XXUAR`:
- `XXCTI_UAR_WORKDAY_EMPLOYEE_MGR`: `EMPLOYEE_ID`, `EMPLOYEE_LEGAL_FIRST_NAME`, `EMPLOYEE_LEGAL_LAST_NAME`,
  `EMAIL_ADDRESS`, `MANAGER_ID`, `MANAGER_FIRST_NAME`, `MANAGER_LAST_NAME`. The ids may be text or numbers (DEV's
  `MANAGER_ID` is text); the release reads them through the view `xxcti_uar_workday_norm`.
- `XXCTI_UAR_EMPLOYEE_RESPONSIBILITIES`: `USER_NAME`, `EMPLOYEE_NUMBER`, `RESPONSIBILITY`, `APPLICATION`,
  `START_DATE`, `END_DATE` (no `LAST_LOGON`). No end-dated rows are expected; if any appear, Page 3 warns, and they are
  still included in the next cycle.
- `XXCTI_UAR_EMPLOYEE_RESPONSIBILITIES_AUDIT`: `EMPLOYEE_NUMBER`, `RESPONSIBILITY`, `APPLICATION`, `LAST_LOGON` are
  used (the source of "Last Used"); it also carries `AUDIT_ID`, `APPROVAL`, `APPROVAL_DATE`, `APPROVER`, `END_DATE`,
  `START_DATE`, `USER_NAME`. Whether the feed is still refreshed is unconfirmed, so treat "Last Used" as best
  available, not guaranteed current.

## Testing
- The **sandbox** is the MRCDEV workspace on the Autonomous DB (SQLcl connection `mrcdev_uar`, schema `XXUAR`) with
  stand-in feeds and fake data; it signs in with APEX accounts instead of SSO. Sandbox feeds must mirror the real column
  types (DEV's Workday `MANAGER_ID` is text; the stub was numeric until that bit a deployment).
- `07_uar_regression_tests.sql` (83 checks) refuses to run while any cycle is open. Simulated sign-ins use
  `apex_session.create_session`, which commits.
- Each deployment pack carries its own test checklist.

## Known gotchas (APEX)
- Never use `p_condition_type`/`p_condition_element`/`p_condition_expression` on `create_page_da_event()` (silent import
  400); encode the condition in JS.
- A generic import 400 can mean a stale copy of the app, or an opaque App Builder error: run the same file through
  SQL Workshop > SQL Scripts to get the real error.
- Don't add a `wwv_flow_imp_page.*` / `wwv_flow_imp_shared.*` parameter with no precedent in the file without grepping
  first (or generate one from a throwaway Page Designer page).
- `DECODE` is SQL-only; use `CASE` in bare PL/SQL.
- A PL/SQL process that does DML and then redirects needs an explicit `commit;`.
- Verify quote-doubling mechanically when editing already-escaped export text.
- Export files never carry credential values, and Universal Theme dropdown floating labels paint a strip across their
  full width, so narrow the whole field, not just the select.

## Deployment discipline
- **Export before import.** An import replaces the whole app: take a fresh export of the target's current app first.
- **ID convention.** Hand-authored component ids in `04_uar_apex.sql` all start `97000000000` (distinct from the
  original app 104's and PMO Hub's ranges); grep the file to confirm an id is unused before adding one.
- **Script size.** `04_uar_apex.sql` is about 130 KB. If SQL Scripts ever refuses it, use App Builder > Import.
- Schema and app move together: schema first, app second, always.

## History
The repo started as a rebuild of the MVP around a proper review-cycle model (see `CHANGELOG.md` for the stage-by-stage
build and the debugging history, including the early confusion over workspace/schema: the real values are workspace
`ct_bsg_apex`, schema `XXUAR`, and they must always be confirmed with the user, never copied from another export).
No mailer is configured, so email notifications are not part of the app; Manager Completion can be exported instead.
